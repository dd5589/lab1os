# Лабораторная работа №1 — Мониторы

## Описание

Программа демонстрирует работу монитора для безопасной синхронизации двух потоков: поставщика и потребителя.

Поставщик с интервалом в одну секунду создаёт событие и передаёт его потребителю. Потребитель ожидает событие, получает его, обрабатывает и выводит результат в консоль.

Всего создаётся и обрабатывается 5 событий.

## Используемые технологии

- C++
- Visual Studio Community
- `std::thread` — создание потоков
- `std::mutex` — защита общих данных
- `std::condition_variable` — ожидание и уведомление о событии
- `std::chrono` — задержка между отправками событий

## Как работает программа

В программе используются два потока:

**Поставщик (Producer):**
1. Ждёт одну секунду.
2. Создаёт объект события.
3. Передаёт его адрес через общий указатель.
4. Устанавливает `ready = true`.
5. Выводит сообщение об отправке.
6. Уведомляет потребителя.

**Потребитель (Consumer):**
1. Ожидает появления события.
2. Получает указатель на объект.
3. Обрабатывает событие.
4. Выводит результат.
5. Освобождает память и сбрасывает `ready`.

Для синхронизации используется один мьютекс и условная переменная. Благодаря `condition_variable` потребитель не проверяет готовность события в бесконечном цикле, а ожидает уведомления.

После отправки всех событий поставщик сообщает о завершении работы, а потребитель завершает свой цикл.

## Передача данных

Для передачи события используется структура `Event`:

```cpp
struct Event {
    int number;
    int value;
};
```

Объект создаётся динамически с помощью `new`, а его адрес передаётся через указатель `eventPointer`.

После обработки потребитель освобождает память с помощью `delete`.

Таким образом, передаётся адрес объекта, а не его сериализованная копия.

## Результат

Реализована синхронизация двух потоков с помощью монитора. Обеспечены последовательная передача и обработка событий, защита общих данных и ожидание без активного опроса.

**Примечание:** в данной версии используются стандартные средства многопоточности C++, а не POSIX `pthread`.
